## 1. 架构总览

```
[浏览器]
   |  Next.js App Router (zh/en 营销 + /app 工作台)
   v
[API Routes / Server Actions]
   |-- Auth
   |-- Jobs (create, status, save edit, export)
   |-- Credits (balance, ledger, demo grant)
   |-- Billing stub (no live charge in Demo)
   v
[Postgres + Prisma]
   +  Object storage (S3 兼容；本地文件系统 adapter 用于 Demo)
   +  LLM Provider 抽象 (OpenAI-compatible)；无 KEY → SeedProvider
```

原则：单仓 Monorepo 或单 Next 应用即可；优先可维护的 MVP，不做微服务。

## 4. 数据模型（Prisma 草案）

```prisma
enum JobStatus {
  queued
  processing
  succeeded
  failed
}

enum Plan {
  free
  pro
  business
  demo_pro      // Demo 模拟
  demo_business
}

model User {
  id            String   @id @default(cuid())
  email         String   @unique
  passwordHash  String?
  plan          Plan     @default(free)
  creditBalance Int      @default(150000)
  createdAt     DateTime @default(now())
  jobs          Job[]
  ledger        CreditLedger[]
}

model Job {
  id              String    @id @default(cuid())
  userId          String
  user            User      @relation(fields: [userId], references: [id])
  status          JobStatus @default(queued)
  sourceFilename  String
  sourceKey       String    // storage object key
  optionsJson     Json      // language, flags
  resultMarkdown  String?   @db.Text
  metaJson        Json?     // characters, glossary, outline
  errorMessage    String?
  creditsReserved Int       @default(0)
  creditsCharged  Int       @default(0)
  createdAt       DateTime  @default(now())
  updatedAt       DateTime  @updatedAt
}

model CreditLedger {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id])
  delta       Int      // 负数为扣，正数为发/退
  reason      String   // job_reserve | job_settle | job_refund | demo_grant | plan_grant
  jobId       String?
  createdAt   DateTime @default(now())
}
```

索引：`Job.userId + createdAt`；`CreditLedger.userId + createdAt`。

## 5. 积分与单位经济

### 5.1 硬规则（实现必须遵守）

1. `creditBalance < estimatedCost` → API 返回 402/403 业务码，**不创建 Job，不调 LLM**  
2. 禁止任何绕过账本的直接 Provider 调用  
3. UI 与 API 均以服务端余额为准  

### 5.2 推荐结算流程

1. `estimateCredits(inputChars, options)`  
2. 事务内：若余额足够，`balance -= estimate`，写 ledger `job_reserve`，创建 job  
3. Worker 跑完：按实际 token（或固定档）计算 `actual`  
4. 若 `actual < reserved`：退回差额 `job_refund`  
5. 若 `actual > reserved`：仅当余额仍够才补扣；否则截断输出并标记部分成功策略（MVP 可禁止实际超过预留：Provider 设 `max_tokens` 封顶）  

**MVP 简化允许**：固定档计价（按上传字符三档），不做 token 精算；仍须走账本。

### 5.3 换算公式（上线前校准）

```
credit_usd   = 月费美元 / 月积分  （例：29.99 / 900000）
raw_cost_usd = (input_tokens * in_price + output_tokens * out_price)
credits      = ceil(raw_cost_usd * SAFETY_MARGIN / credit_usd)
SAFETY_MARGIN >= 2.0
```

环境变量建议：

- `CREDITS_SAFETY_MARGIN=2`  
- `CREDITS_PER_1K_INPUT_CHARS=...`（固定档时用）  
- `DEMO_MODE=true`  

**占位套餐数字未经实测，不得写死为生产计费唯一真相；README 须标注 “calibrate before launch”。**

### 5.4 Demo 发分

- `POST /api/demo/grant-credits`（仅 `DEMO_MODE=true`）  
- `POST /api/demo/set-plan` → `demo_pro` / `demo_business`  
- 生产构建：`DEMO_MODE` 必须为 false，路由直接 404

## 6. LLM 管线

### 6.1 接口

```ts
interface LlmProvider {
  runAdaptPipeline(input: {
    text: string
    options: AdaptOptions
  }): Promise<{
    markdown: string
    meta: { outline?: unknown; characters?: unknown; glossary?: unknown }
    usage: { inputTokens: number; outputTokens: number }
  }>
}
```

实现：

- `OpenAICompatibleProvider`（`LLM_BASE_URL` + `LLM_API_KEY` + `LLM_MODEL`）  
- `SeedProvider`（无 KEY 或 `LLM_PROVIDER=seed`）  

### 6.2 步骤（可多 call，串行）

1. `parse_and_outline`  
2. `characters_and_glossary`  
3. `cultural_adapt`  
4. `format_short_drama_script`  

每步限制 `max_tokens`；总预留积分覆盖最坏路径。

### 6.3 Worker

- API 创建 job 后 `queued`  
- 可由：  
  - Next.js 内 `after()` / 后台 async（仅 Demo 单机），或  
  - cron 每 N 秒领取 `queued`  
- 领取时 CAS：`queued` → `processing`  
- 超时（如 10 分钟）标记 `failed` 并退款

## 7. 存储与导出

| 对象 | Key 示例 |
|------|----------|
| 源文件 | `uploads/{userId}/{jobId}/source` |
| 导出 | `exports/{userId}/{jobId}/script.{pdf\|docx\|txt}` |

导出：

- TXT / Markdown：直接  
- DOCX：`docx` 库  
- PDF：`pdfkit` 或 headless 打印（MVP 可选先做 TXT+DOCX，PDF 第二优先）  

需求验收写了三种格式：尽可能都做；若时间不够，PDF 可用「打印友好 HTML」占位并在 README 标明。

## 10. 安全

- 所有 App API 鉴权；IDOR：job 必须校验 `userId`
